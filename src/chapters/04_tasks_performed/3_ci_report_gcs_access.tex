\section{Development of a Reverse Proxy for Google Cloud Storage}
\label{sec:gcs-proxy}

\subsection{Context}
\acf{CI} pipelines automatically generate numerous artifacts such as Playwright reports, Cypress reports, visual regression reports, code coverage reports and static analysis reports. These artifacts are essential for validating software quality and approving pull requests throughout the development lifecycle.

Initially, these reports were stored using GitHub Actions Artifacts. Although this solution integrates naturally with GitHub workflows, it presents several limitations. The storage consumed by artifacts continuously increases over time, especially for large visual regression reports, leading to higher infrastructure costs. Moreover, GitHub artifacts cannot be accessed directly through a web browser. Developers must download the archive, extract its contents, and open the report locally before consulting it.

To overcome these limitations, Rakuten France decided to migrate \ac{CI} artifacts to private \acf{GCS} buckets. \ac{GCS} provides scalable, durable and cost-effective object storage. However, because the buckets remain private, reports cannot be accessed without Google Cloud authentication.

To provide secure yet transparent access to these reports, a reverse proxy application was developed. The application authenticates against Google Cloud Storage on behalf of internal users and exposes reports through \acs{HTTP} endpoints while keeping the storage infrastructure completely private.

\subsection{Objectives}

The project pursued both technical and educational objectives.

\begin{itemize}
\item Keep Google Cloud Storage buckets private and secure.
\item Allow internal access to reports through a Rakuten web application.
\item Simplify report consultation directly from a browser.
\item Provide report discovery, verification and download features.
\item Discover the complete software lifecycle from requirements analysis to deployment and maintenance.
\end{itemize}

\subsection{System Architecture}

The application follows a reverse proxy architecture. Every request is received by the proxy instead of directly reaching Google Cloud Storage.

\begin{figure}[H]
\centering
\includegraphics[width=.95\textwidth]{../assets/tools/rakuten_technical_environment.png}
\caption{Overall architecture of the reverse proxy.}
\label{fig:gcs_architecture}
\end{figure}

The processing workflow is summarized below:

\begin{enumerate}
\item Receive an incoming HTTP request.
\item Extract the bucket name and object path.
\item Authenticate using a Google Cloud Service Account.
\item Reuse a cached OAuth token whenever possible.
\item Request the object through the Google Cloud Storage API.
\item Stream the object directly to the client.
\item Return the corresponding HTTP response.
\end{enumerate}

\subsection{Authentication and Token Caching}

The Infrastructure team provides the application with a Google Cloud Service Account JSON credential. During startup, the application loads these credentials and generates an OAuth access token.

Since generating a token for every request would introduce unnecessary latency, the application stores the generated token in memory until its expiration time. When the token expires, a new one is automatically generated and replaces the previous token. This caching strategy significantly reduces authentication overhead under heavy workloads.

\subsection{Streaming Mechanism}

Instead of downloading the complete object before sending it to the client, the application streams files directly from Google Cloud Storage to the HTTP response. Streaming reduces memory consumption, decreases latency, and allows very large HTML reports and visual regression artifacts to be served efficiently.

\subsection{Technology Stack}

The project is developed using TypeScript as the primary programming language, with
Node.js as the runtime environment and pnpm as the package manager. The HTTP server
is implemented using the Hono framework, a lightweight and high-performance web
framework designed for building modern HTTP servers and APIs with JavaScript and
TypeScript.

\textbf{Hono} is based on Web Standard APIs, enabling applications to run across multiple
runtimes such as Node.js, Bun, Deno, and Cloudflare Workers. It also provides a simple Express-like routing system while maintaining a minimal footprint.

The web interface of the application is developed using standard web technologies,
including HTML, CSS, and JavaScript.
 
Google Cloud Storage is used as the storage solution for hosting CI-generated
artifacts, while Google Cloud Service Account credentials provide secure and
controlled authentication for accessing cloud resources.

The project source code is hosted in an internal GitHub organization repository,
ensuring that access is restricted to authorized users within the company.

\subsection{REST API}

The application exposes several REST endpoints.

\subsubsection{Functional Endpoints}

The basic endpoint structure is defined as follows:

\[
\texttt{<Operation>/<Bucket\ name>/<FilePath>}
\]

where the \texttt{FilePath} parameter can represent either a direct file name
or a nested path pointing to a file or folder within the specified bucket.

Concretely, the application provides the following endpoints:

\begin{itemize}
    \item \texttt{GET /gcs/<bucket>/<filePath>}: Serve a report file directly from Google Cloud Storage.
    \item \texttt{GET /download/<bucket>/<filePath>}: Download a report or a set of files as a ZIP archive.
    \item \texttt{GET /check-exist/<bucket>/<filePath>}: Verify whether a specific report or file exists.
    \item \texttt{GET /search/<bucket>/<filePath>}: Search for the latest report matching a given prefix or suffix.
    \item \texttt{GET /buckets}: List all accessible Google Cloud Storage buckets.
\end{itemize}

\subsection{Testing}

A dedicated Google Cloud Storage bucket was created for integration testing.

The test suite validates:

\begin{itemize}
\item Retrieval of HTML reports.
\item Retrieval of JSON resources.
\item Retrieval of static assets.
\item Access to non-existing objects.
\item Report discovery.
\item Report download.
\item Bucket listing.
\item Token caching under concurrent requests.
\end{itemize}

Load tests were also performed to verify that cached authentication tokens are effectively reused, reducing the number of OAuth authentication requests while maintaining low response times.

\subsection{Summary}

The developed reverse proxy provides secure and efficient access to CI artifacts stored in private Google Cloud Storage buckets. By combining authenticated access, token caching, streaming, monitoring endpoints and a simple web interface, the application improves report accessibility while preserving the security of the underlying storage infrastructure. Furthermore, the project provided valuable experience covering the complete software engineering lifecycle, from requirements analysis and architecture design to implementation, testing and deployment.
